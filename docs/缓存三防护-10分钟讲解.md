# 缓存三防护：10 分钟讲解稿

> 用法：面试时按时间轴讲，每段先给结论，再给代码位置和验证数据。
> 核心不是背“穿透/击穿/雪崩”的定义，而是说清楚：不这么做会怎样、你怎么验证。

## 0:00–1:00 场景

动态详情是典型的读多写少接口：一篇热门动态可能被反复打开，读请求远多于发布/删除。
MySQL 单行主键查询不慢，但热点流量下会把连接池和 IO 打满，所以详情走 Redis 缓存。

一句话：**缓存的目标不是让单次请求更快，而是把数据库从热点读里摘出来。**

## 1:00–3:00 三个问题

| 问题 | 触发方式 | 不处理的后果 |
|---|---|---|
| 穿透 | 大量请求查一个不存在的 ID | 缓存永远 miss，每次都打 MySQL |
| 击穿 | 某个热点 key 刚好过期 | 过期瞬间并发全部回源，数据库瞬时被打穿 |
| 雪崩 | 大批 key 同一时间过期 / Redis 故障 | 请求同时涌向 MySQL，可能拖垮数据库 |

## 3:00–6:00 实现

代码位置：`service/cache.go`、`service/post.go`。

**① 空值缓存（防穿透）**

- 查库为空时写 `weiyu:post:null:{id}`，TTL 1 分钟；
- 后续请求先看空值标记，命中直接返回 404，不再查库；
- TTL 不能太长，否则新建的数据会在一段时间内“看不见”。

**② singleflight（防击穿）**

- `postDetailGroup.Do(postDetailKey(id), ...)` 把同一篇动态的并发回源合并成一次；
- 进入 singleflight 后做一次双重检查，排队期间别人已回填就直接用；
- 只有拿到 MySQL 结果的那个请求回填缓存。

**③ TTL 抖动（防雪崩）**

- `jitterTTL` 在 10 分钟基础上加 0~50% 随机值；
- 同一批写入的 key 不会在同一秒集体过期。

**④ 写路径：Cache-Aside + 提交后删除**

- 删除动态在事务里级联删点赞、评论、动态；
- **事务提交后**再删详情、空值、点赞计数三个 key；
- 顺序不能反：先删缓存再提交，事务一旦回滚，就会出现“缓存没了、数据还在”的脏状态。

**⑤ 降级**

- Redis 读失败：记日志，继续查 MySQL，不把缓存故障放大成接口故障；
- 登出校验是可用性优先：Redis 不可用时放行，代价是故障期间登出失效。

## 6:00–8:00 怎么验证

用 `cmd/bench` 对 `/api/v1/posts/1` 各打 5000 请求（100 并发，预热 200），
同时读取 MySQL `Com_select` 增量：

| 指标 | 缓存开 | 缓存关 |
|---|---:|---:|
| QPS | 47,745 | 37,860 |
| P99 | 6.29 ms | 7.55 ms |
| DB SELECT | **0** | **5,000** |

关键结论：

- 缓存把 5000 次回源降到 0，这是保护数据库；
- 本机 MySQL 单行查询很快，所以 QPS 只高约 26%，不要把它吹成几十倍；
- 真实网络、连接池紧张、热点突增时，缓存的价值主要在“数据库不被打穿”和尾部延迟。

复现命令见 README 第 7 节。

## 8:00–9:30 取舍与边界

- **一致性**：删缓存 + 短 TTL 是最终一致；删除后、缓存失效前可能读到旧值。
  如果要更强一致性，需要延迟双删、订阅 binlog 或版本号，成本更高。
- **空值 TTL**：太短防不住穿透，太长会让新数据延迟可见；这里取 1 分钟。
- **singleflight**：合并请求会阻塞等待，必须带 context/超时；只适合热点 key，不是所有读都无脑加。
- **固定窗口限流**：窗口边界可能放过约 2 倍流量，第一道粗保护够用，精确限流要滑动窗口/令牌桶。

## 9:30–10:00 收尾

一句话总结：

> 缓存三防护分别解决“查不存在的”“热点过期的”“集体过期的”三类回源风暴；
> 我用空值缓存、singleflight、TTL 抖动实现，并用缓存开/关压测验证了 DB 回源从 5000 降到 0。

## 附：面试官可能追问

1. 为什么不用 `SETNX` 做互斥，而用 singleflight？
   ——单机进程内合并更轻；多实例部署时需要分布式锁或逻辑过期。
2. 删除缓存失败怎么办？
   ——短 TTL 兜底；也可以重试/消息补偿，当前项目没做到这一步。
3. 空值缓存会不会导致“刚发布就 404”？
   ——会有一个 TTL 窗口；发布时没有删空值 key，这是已知限制，可以补。
4. 为什么缓存整个 Post 而不是字段？
   ——详情页一次要全部字段，整体缓存减少拼装和多次查询；更新频率低。
5. Redis 挂了接口还能用吗？
   ——读路径降级查 MySQL；限流和登出会受影响，这是可用性优先的取舍。
